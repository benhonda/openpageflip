Most assistants have seen {upstream.name} and {upstream.reactPackage}, and honestly that's the problem: this library isn't either of them. The names are different and there's no compatibility layer, so an agent working from memory writes against an API that isn't there. The fix is just pointing it at these docs before it writes anything.

## The docs as plain text

Every page here is also served as Markdown, generated from the same source at every build, so an agent can read it without scraping HTML.

- <a href={llmsTxt.index}><code>{absoluteUrl(llmsTxt.index)}</code></a>: the index. A short description and links to the other two. If you're not sure which to give it, give it this one.
- <a href={llmsTxt.guides.path}><code>{absoluteUrl(llmsTxt.guides.path)}</code></a>: {llmsTxt.guides.set.description}. Small enough to read whole, and enough to build a book from.
- <a href={llmsTxt.full}><code>{absoluteUrl(llmsTxt.full)}</code></a>: everything, API reference included.

Tools that index docs from a URL (Cursor's docs setting, for one) can be given the site address, <a href={siteUrl}><code>{siteUrl}</code></a>, and will find the same pages.

## Tell it once

Put this in the file your agent reads at the start of every session - `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`, a Cursor rule, whichever yours is - and you don't have to say it again.

<Code
  lang="md"
  title="AGENTS.md"
  code={`## OpenPageFlip

Page-flip effect for HTML content: \`${corePkg.name}\` (plain JavaScript) and \`${reactPkg.name}\` (React ${reactMajor}).
It is not ${upstream.name} or ${upstream.package}: the API is different, so read the docs before writing code.

- Guides and examples: ${absoluteUrl(llmsTxt.guides.path)}
- Everything, API reference included: ${absoluteUrl(llmsTxt.full)}
`}
/>

## Or ask once

For a one-off, a prompt that starts with the docs does the same job. Fill in the bits in angle brackets.

<Code
  lang="text"
  title="prompt"
  code={`Read ${absoluteUrl(llmsTxt.guides.path)} and then add an OpenPageFlip book to <the page> whose pages are <what the pages are>. Follow those docs rather than what you know about ${upstream.name} or ${upstream.package}; the API is different.`}
/>
